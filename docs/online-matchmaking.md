# 6人オンラインマッチング設計

3人対3人(黒3・白3)の6人を、ネット越しにマッチングして対局させる仕組みの設計。
前提は「お金をなるべくかけない」「Claudeがコマンドだけで設定・デプロイ・テストできる」こと。

## 結論

**Cloudflare Workers + Durable Objects(以下DO)を推奨。**

- 無料プランで始められる(クレジットカード不要)。カジュアル規模なら当面 0円、伸びても月 $5〜
- 「1部屋 = 1つのDO」なので、手番・30秒秒読み・CPU代打ちを**サーバー側の1か所で判定**できる。今の `src/server/room.ts` をほぼそのまま載せられた
- `wrangler dev` で本番と同じランタイムがローカルで動く。アカウントなしで開発・テストでき、デプロイも `wrangler deploy` 1発
- 言語は TypeScript のまま。対局ロジック(`src/shared/`)をクライアント(オフラインモード・CPU)と共有し続けられる

このリポジトリの `cloud/` に動くスパイクを入れた(後述)。

### サーバー言語について

Go / Ruby / Crystal も検討したが、**DO を使うなら TypeScript 一択**(Go は Wasm 経由で可能だが手間が大きい、Crystal は動かない)。
Crystal で書きたい場合は Fly.io に Crystal サーバーを置く構成になるが、対局ロジックをクライアント(TS)とサーバー(Crystal)で二重に持つことになるので、製品版では勧めない。

## 全体構成

```
スマホ(Capacitor) / ブラウザ
   │  WebSocket
   ▼
Worker(入口・ルーティング・静的ファイル)
   ├─ /api/queue        → MatchmakerDO("global")   待ち行列。成立したら部屋と席を通知
   ├─ POST /api/rooms   → 招待コードを発行して GameRoomDO を作る
   └─ /api/rooms/:id/ws → GameRoomDO(部屋ごと)     既存の Room クラスで対局を進行
```

### クイックマッチ

1. クライアントは `/api/queue?name=..` に WebSocket で接続して並ぶ
2. 6人揃ったら即成立。揃わなくても、**先頭の人が20秒待ったら、いる人だけで成立し残りはCPU**
3. 席は 黒1→白1→黒2→白2→黒3→白3 の順に詰める(2人なら黒1と白1、つまり人対人になる)
4. MatchmakerDO が部屋を作り、各自に `{roomId, token, seat}` を返す → クライアントは部屋に繋ぎ直す
5. 全員が部屋に揃ったら開始。来ない人がいても15秒で開始し、その席はCPUが打つ

同じ名前の人には「たろう2」のように番号を付ける。

### フレンド部屋(招待コード)

- `POST /api/rooms` で6文字のコード(0/O、1/I/L など紛らわしい文字を除外)を発行
- `/api/rooms/<コード>/ws` に入ると、今のプロトタイプと同じく好きな席に座って「対局開始」
- コードは大文字小文字を区別しない。LINEで共有しやすい

### 切断と再接続

- 部屋に入ると `token` が発行される(クイックマッチはマッチ時に発行)。端末に保存しておく
- 対局中に切れたら、その席は**CPUが代わりに打つ**(既存の動き)
- 同じ `token` で繋ぎ直すと席に戻る。Wi-Fi⇔4G切替などで古い接続が残っていたら新しい方を優先
- 偽の `token` ではクイックマッチの部屋に入れない(403)

### 30秒秒読みの権威

- 秒読みは部屋のDOが持つ。締切時刻 `deadline` とサーバー時刻 `serverNow` を毎回配信し、クライアントは表示するだけ(今と同じ)
- 1部屋が1か所でしか動かないので、二重に手番が進むことはない

## 費用の見積もり

Cloudflare DO の料金(2026年11月、[公式](https://developers.cloudflare.com/durable-objects/platform/pricing/)):

| | 無料プラン | 有料プラン(月$5〜) |
| --- | --- | --- |
| リクエスト | 10万/日 | 100万/月込み、以降 $0.15/100万 |
| 実行時間 | 13,000 GB秒/日 | 40万 GB秒/月込み、以降 $12.50/100万GB秒 |
| 保存(SQLite) | 5GB | 5GB込み |

- WebSocket の受信メッセージは20通で1リクエスト換算、送信は無料
- DOのメモリは128MB換算。**接続を張りっぱなしにすると、その間ずっと実行時間が課金される**

1局(9路・6人・約15分)あたり:

- 実行時間: 900秒 × 0.125GB ≈ **113 GB秒**
- リクエスト: 接続6 + 手やピンの受信(~150通 ÷ 20)≈ **20程度**(ほぼ無視できる)

→ 無料プランで **1日 約110局(のべ660人)** まで。有料プランなら月 約3,500局が込みで、以降1局あたり約0.2円。
次の段階で WebSocket Hibernation(後述)に切り替えると、待ち時間中の課金がなくなり、これの数倍〜10倍程度まで伸びる見込み。

## スパイク(`cloud/`)

- `src/queue.ts` 待ち行列の純粋ロジック(単体テストあり)
- `src/matchmaker-do.ts` クイックマッチのDO
- `src/room-do.ts` 部屋のDO。`src/server/room.ts` を**無改造で**包んでいる
- `src/worker.ts` 入口。`public/` の既存クライアントもここから配信し、`/ws?room=` の互換ルートで今のUIがそのまま遊べる
- `test/e2e.mjs` `wrangler dev` に対して6人分のクライアントを模擬するテスト
  1. 6人揃うと即マッチして全員人間で開始
  2. 2人だけ → 待ち時間後に CPU 4人で開始 → 白の人が切断 → CPUが代打ち → 同じtokenで戻ると席に復帰
  3. 招待コードでフレンド部屋を作り、13路で開始
  4. 既存UI用の互換ルート

ローカルではすべて通過済み。動かし方は `cloud/README.md`。

## 製品化までにやること

1. **状態の永続化とHibernation**: 今のスパイクは対局状態をメモリにだけ持つので、デプロイやDOの再起動で進行中の対局が消える。手の列をDOのSQLiteに保存し、秒読みは `setAlarm` に置き換え、WebSocket Hibernation API を使う(費用も下がる)
2. **クライアントの対応**: 「クイックマッチ」「部屋を作る/コードで入る」画面、`token` の保存(Capacitor Preferences)、接続先URLの設定(アプリ内からは絶対URLで繋ぐ)
3. **再接続を名前ではなくtokenで判定**: 今の `Room` は同名で席に戻る仕組みなので、席にtokenを持たせる
4. **マッチングの調整**: 待ち時間、盤サイズ別の行列(`queue:9` / `queue:13`)、人数が増えてきたら待ちを延ばす、など
5. **最低限の荒らし対策**: 名前の長さ・接続数のレート制限。ログインはしばらく不要(匿名でよい)

## てさおさんに必要な作業

Claude はアカウントを作れないので、デプロイする段階で次だけお願いしたい。ローカル開発・テストにはどれも不要。

1. Cloudflare アカウントを作る(無料、カード不要)
2. 「Edit Cloudflare Workers」テンプレートで API トークンを作る
3. トークンとアカウントIDを、Claude の環境変数(`CLOUDFLARE_API_TOKEN` / `CLOUDFLARE_ACCOUNT_ID`)か GitHub Actions のシークレットに登録する。Claude の環境から使う場合は、ネットワーク設定で `api.cloudflare.com` への通信を許可する

これで `npm run deploy` すると `https://go3v3.<サブドメイン>.workers.dev` で遊べるようになる。
